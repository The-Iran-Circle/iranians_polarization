# DPP Datapage — Local Build Instructions

A bilingual (Persian/English) data website for the Diaspora Politics Project survey, built with Quarto + Observable Plot. All statistics are pre-computed in R; the site is fully static (no server).

## One-time setup

### 1. Install Quarto

Download from <https://quarto.org/docs/get-started/>. Single installer for macOS / Windows / Linux.

Verify:
```bash
quarto --version    # should print 1.4 or later
```

### 2. Install required R packages

In R or RStudio:
```r
install.packages(c("readxl", "dplyr", "tidyr", "forcats", "jsonlite"))
```

### 3. Place your data file

Put `DPP_March 23.xlsx` in the project root (same folder as `_quarto.yml`).
If the filename differs, edit the `DATA_FILE` variable at the top of `R/build_widget_data.R`.

## Daily workflow

### Whenever data or analysis changes

```bash
Rscript R/build_widget_data.R
```

This regenerates the four JSON files in `data/` that the site reads:

- `responses.json` — tidy long-format raw responses for the jitter plot
- `summary.json`   — per (item × group) means, SDs, 95% CIs
- `stats.json`     — per item: ANOVA F/p/η², all pairwise Cohen's d
- `labels.json`    — bilingual labels (English + Persian) for items, groups, scales

You should see output like:
```
✔ responses.json  4912 rows
✔ summary.json     65 rows
✔ stats.json       13 items
✔ labels.json      1 batteries, 1 grouping(s)
```

### Preview the site locally

```bash
quarto preview
```

This opens your browser at `http://localhost:NNNN` and **live-reloads** when you save any `.qmd` file. Keep this running while you write.

### Build a static copy

```bash
quarto render
```

Outputs to `_site/`. You can open `_site/index.html` directly, or zip the folder and host it anywhere.

### Publish to GitHub Pages

First time:
```bash
git init && git add . && git commit -m "Initial site"
# create a repo on github.com, then:
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO.git
git push -u origin main
quarto publish gh-pages
```

After that, just `quarto publish gh-pages` — Quarto remembers the destination.

## How to add another battery

Open `R/build_widget_data.R`. Find the section labeled `BATTERY 1: Symbolic National Identity`. Below it, add a new block:

```r
# ════════════════════════════════════════════════════════════════════════════
#  BATTERY 2: RWA / ACT
# ════════════════════════════════════════════════════════════════════════════
rwa_items <- c("ACT_submis_pro_1", "ACT_submis_pro_2", ...)
rwa_labels_en <- c("Submission item 1", "Submission item 2", ...)
rwa_labels_fa <- c("...", "...", ...)

rwa <- build_battery(
  battery_id   = "rwa",
  item_ids     = rwa_items,
  recoder      = recode_likert,    # or your own recoder
  grouping_var = "pol_analysis",
  group_levels = pol_order
)
```

Then **append to the combined outputs** (currently the file just uses `sym$...` directly — change those lines to `rbind(sym$responses, rwa$responses)` etc.) and add a corresponding entry to the `labels$batteries` list.

After running the script, the new battery will automatically appear in the explorer dropdown (the `selectedBattery` selector in `explorer.qmd` walks every key of `labels.batteries`).

## How to add another grouping variable

Right now, the only grouping is `pol_analysis` (political group). To add Gender, Generation, Religiosity, etc.:

1. In `R/build_widget_data.R`, call `build_battery()` again with `grouping_var = "Gender"` (and the appropriate ordered levels).
2. Append the results to `all_responses`, `all_summary`, `all_stats`.
3. Add a new entry under `labels$groupings`.
4. In `explorer.qmd`, expose a second dropdown that lets the user pick the grouping.

## Troubleshooting

- **Persian text shows as boxes** → Check that `styles.css` is loaded (DevTools → Network) and that the Vazirmatn font from Google Fonts isn't blocked.
- **Widget shows "Loading…" forever** → Open DevTools console. Most likely a JSON file 404 — check `data/` exists and was generated. Paths in `findings/*.qmd` use `../data/...` (relative); paths in `explorer.qmd` use `data/...`.
- **Numbers look wrong** → Recompute and check the R script output. The R script is the single source of truth.

## Data privacy reminder

The raw Excel file contains PII columns: `RecipientLastName`, `RecipientFirstName`, `RecipientEmail`, `ExternalReference`. **Do not commit the raw file to GitHub.** Add to `.gitignore`:

```
DPP_March 23.xlsx
*.xlsx
```

When archiving the dataset publicly (e.g., on OSF), strip those columns first.
